# Технологии FlautCompany

Этот документ содержит описание основных технологий, разрабатываемых в экосистеме **FlautCompany**.

Технологии разделены по направлениям: кибербезопасность, искусственный интеллект и программная инфраструктура.

---

# Обзор

На текущем этапе технологическая экосистема FlautCompany включает несколько основных разработок:

| Технология   | Направление             | Назначение                         |
| ------------ | ----------------------- | ---------------------------------- |
| `.fsecurity` | Кибербезопасность       | Защита данных внутри приложения    |
| `FlautGuard` | AI Security             | Защита языковых моделей            |
| `FlautFast`  | Искусственный интеллект | Разработка AI и LLM-технологий     |
| `FlautCloud` | Инфраструктура          | Облачное хранение и тестовая среда |

Технологии предназначены для разных уровней программной системы и могут использоваться совместно.

---

# .fsecurity

## Определение

**`.fsecurity`** — криптографический модуль FlautSecurity, предназначенный для защиты данных непосредственно внутри программного проекта.

Модуль не является отдельным сервером, прокси или самостоятельным сетевым сервисом.

Он интегрируется непосредственно в приложение и обрабатывает данные в рамках его программной логики.

## Назначение

`.fsecurity` предназначен для защиты различных категорий данных, включая:

* пользовательские файлы;
* запросы;
* ответы;
* логи;
* метаданные;
* сессии;
* внутренние данные приложения.

Основной принцип заключается в том, что данные хранятся в зашифрованном виде.

Для отдельных объектов могут использоваться независимые криптографические ключи.

## Шифрование

В реализации используется **AES-256-GCM**.

AES-256 обеспечивает шифрование данных, а GCM предоставляет одновременно конфиденциальность и проверку целостности зашифрованного объекта.

Упрощённо процесс выглядит следующим образом:

```text
Исходные данные
      │
      ▼
 .fsecurity
      │
      ├── генерация / получение ключевого материала
      │
      ▼
 AES-256-GCM
      │
      ▼
Зашифрованный объект
      │
      ▼
Хранилище / сервер
```

Система рассчитана на то, чтобы компрометация хранилища не означала автоматическое раскрытие содержимого всех объектов.

# FlautGuard

## Определение

**FlautGuard** — технология FlautSecurity для дополнительной защиты систем искусственного интеллекта и больших языковых моделей.

FlautGuard располагается между пользователем и моделью и выполняет обработку входных и выходных данных.

Упрощённая схема:

```text
Пользователь
     │
     ▼
  CleanIn
     │
     ▼
  DetectIn
     │
     ▼
    LLM
     │
  ShieldIn
     │
     ▼
 FilterOut
     │
     ▼
 Пользователь
```

---

## CleanIn

`CleanIn` отвечает за предварительную обработку входных данных.

Основная задача компонента — нормализация текста перед передачей его следующим уровням системы.

Это позволяет уменьшить влияние различных вариантов представления одного и того же вредоносного ввода.

Обрабатываться могут, например:

* необычные последовательности символов;
* различные варианты Unicode;
* избыточное форматирование;
* попытки обойти правила обнаружения через изменение представления текста.

---

## DetectIn

`DetectIn` отвечает за обнаружение подозрительных пользовательских запросов.

Одним из основных классов угроз являются **prompt injection** — попытки пользователя изменить поведение модели посредством специально сформированного ввода.

DetectIn классифицирует входные данные до передачи модели.

При обнаружении подозрительного запроса система может применить соответствующую политику обработки.

---

## ShieldIn

`ShieldIn` представляет собой дополнительный уровень защиты внутри AI-контура.

В архитектуре FlautGuard используются механизмы дополнительного контроля обработки входных данных моделью.

Этот уровень отличается от внешнего классификатора тем, что располагается ближе к самой модели.

Таким образом, FlautGuard не ограничивается только проверкой текста перед отправкой запроса.

---

## FilterOut

`FilterOut` анализирует результат, сформированный моделью.

Основная задача — обнаружение информации, которая не должна попадать пользователю или внешней системе.

Для этого могут использоваться:

* NER;
* регулярные выражения;
* правила обнаружения чувствительных данных;
* дополнительные проверки содержимого.

Упрощённо:

```text
Ответ модели
     │
     ▼
 FilterOut
     │
     ├── безопасный → пользователю
     │
     └── подозрительный → обработка по политике
```

# FlautFast

## Определение

**FlautFast** — AI-направление FlautCompany, связанное с разработкой технологий искусственного интеллекта и больших языковых моделей.

Направление включает исследования и разработку:

* LLM;
* AI-агентов;
* AI-инфраструктуры;
* систем обработки естественного языка;
* механизмов взаимодействия с языковыми моделями;
* технологий безопасности AI.

FlautGuard является отдельным защитным компонентом, предназначенным для использования с AI-системами.

---

# FlautCloud

## Определение

**FlautCloud** — проект облачного хранения файлов FlautCompany.

Проект предоставляет пользователям возможность загружать и скачивать файлы.

Для взаимодействия с системой используется Telegram-бот:

**@flautcloud_bot**

FlautCloud также используется как практическая среда для тестирования технологий компании.

В частности, проект используется для эксплуатации и тестирования `.fsecurity` на пользовательских данных.

---

# Взаимодействие технологий

Технологии FlautCompany могут образовывать многоуровневую систему:

```text
                   FlautCompany
                        │
              ┌─────────┴─────────┐
              │                   │
        FlautSecurity             AI
              │                   │
       ┌──────┴──────┐            │
       │             │            │
 .fsecurity     FlautGuard     FlautFast
       │             │            │
       ▼             ▼            ▼
     Данные          AI          LLM
```

В таком сценарии `.fsecurity` и FlautGuard решают разные задачи.

`.fsecurity` защищает данные.

FlautGuard защищает взаимодействие с AI-системой.

FlautFast является технологическим AI-направлением.

# Два уровня безопасности

Одним из принципов экосистемы FlautSecurity является разделение безопасности данных и безопасности модели.

```text
┌──────────────────────────────────────┐
│             Приложение               │
│                                      │
│  ┌────────────────────────────────┐  │
│  │          FlautGuard             │  │
│  │          AI Security            │  │
│  └────────────────────────────────┘  │
│                                      │
│  ┌────────────────────────────────┐  │
│  │           .fsecurity            │  │
│  │          Data Security          │  │
│  └────────────────────────────────┘  │
│                                      │
└──────────────────────────────────────┘
```

Такое разделение позволяет не возлагать защиту всей системы на один механизм.

Даже если приложение одновременно использует LLM и хранит пользовательские данные, защита этих двух уровней может осуществляться независимо.

# Принцип интеграции

Технологии FlautCompany ориентированы на интеграцию в существующие программные проекты.

В зависимости от технологии это может быть:

* библиотека;
* модуль;
* middleware;
* программный компонент;
* отдельный слой внутри существующего приложения.

Главная идея заключается в том, чтобы разработчик мог добавить дополнительный уровень защиты без полной перестройки существующей архитектуры.

---

# Статус технологий

Некоторые разработки FlautCompany находятся в стадии активного развития и тестирования.

Экспериментальные проекты используются для проверки архитектурных решений в реальных условиях.

По мере развития технологий их архитектура, API, методы интеграции и область применения могут изменяться.

Актуальные технические характеристики должны определяться соответствующей документацией конкретной версии технологии.
