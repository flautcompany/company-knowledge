# Искусственный интеллект — FlautCompany

Этот документ описывает направление искусственного интеллекта в **FlautCompany**, включая FlautFast, большие языковые модели и технологии безопасности AI-систем.

---

# FlautFast

**FlautFast** — направление FlautCompany, посвящённое разработке и исследованию технологий искусственного интеллекта.

Направление включает работу с большими языковыми моделями, AI-агентами и программной инфраструктурой для AI-систем.

FlautFast рассматривается как отдельный технологический слой экосистемы FlautCompany.

```text id="v0k5pz"
FlautCompany
      │
      └── FlautFast
            │
            ├── LLM
            ├── AI-агенты
            ├── AI-инфраструктура
            └── AI Security
```

---

# Большие языковые модели

Одним из направлений FlautFast являются системы, построенные на основе больших языковых моделей.

LLM могут использоваться для:

* обработки естественного языка;
* генерации текста;
* анализа информации;
* взаимодействия с пользователем;
* автоматизации задач;
* работы в составе AI-агентов.

При этом использование LLM создаёт отдельный класс информационных угроз, которые не полностью покрываются традиционными средствами защиты приложений.

---

# Особенности безопасности LLM

В отличие от обычного программного интерфейса, языковая модель работает с инструкциями и естественным языком.

Пользователь может передавать модели не только данные, но и инструкции.

Это создаёт принципиально другую поверхность атаки.

Например, пользовательский ввод может содержать попытку:

* изменить приоритет первоначальных инструкций;
* заставить модель раскрыть внутреннюю информацию;
* изменить последовательность действий AI-агента;
* обойти ограничения;
* заставить модель обработать недоверенные данные как инструкции.

Одним из наиболее известных классов таких атак является **prompt injection**.

---

# FlautGuard

Для дополнительной защиты AI-систем FlautSecurity разработал **FlautGuard**.

FlautGuard является отдельным защитным слоем, который может располагаться вокруг языковой модели.

Основная архитектура:

```text id="n7d3xq"
Пользователь
     │
     ▼
  CleanIn
     │
     ▼
  DetectIn
     │
     ▼
    LLM
     │
  ShieldIn
     │
     ▼
 FilterOut
     │
     ▼
  Ответ
```

В этой архитектуре каждый компонент решает отдельную задачу.

---

# CleanIn

`CleanIn` занимается предварительной обработкой входных данных.

Главная задача — нормализовать пользовательский текст до передачи его классификатору и модели.

Это особенно важно потому, что один и тот же смысл может быть представлен множеством различных способов.

Например, атакующий может использовать:

* нестандартные Unicode-символы;
* управляющие символы;
* необычное форматирование;
* различные варианты разделения текста;
* смешивание нескольких представлений символов.

Нормализация уменьшает количество таких вариантов.

---

# DetectIn

`DetectIn` анализирует входной запрос и определяет вероятность того, что он содержит попытку атаки.

Основной класс угроз — prompt injection.

Вместо того чтобы отправлять любой пользовательский ввод непосредственно модели, система сначала проводит его через отдельный уровень анализа.

Упрощённо:

```text id="e4n8zw"
Запрос
  │
  ▼
DetectIn
  │
  ├── нормальный ──────► LLM
  │
  └── подозрительный ──► политика безопасности
```

Важно, что классификатор не является абсолютным барьером.

Любая система классификации может иметь ложные срабатывания и пропуски.

Поэтому DetectIn является частью многоуровневой архитектуры FlautGuard.

---

# ShieldIn

`ShieldIn` представляет собой дополнительный защитный слой, связанный с внутренней обработкой AI-системы.

Его назначение — не ограничиваться исключительно анализом пользовательского текста.

В архитектуре FlautGuard этот слой используется для дополнительного контроля поведения AI-контура.

Таким образом, защита строится на нескольких уровнях:

```text id="y3w6sa"
Входной текст
      │
      ▼
  CleanIn
      │
      ▼
  DetectIn
      │
      ▼
  ShieldIn
      │
      ▼
    LLM
```

---

# FilterOut

Проверка не заканчивается после получения ответа от модели.

Даже безопасный на первый взгляд запрос может привести к нежелательному результату.

Поэтому FlautGuard анализирует ответ модели перед его передачей пользователю.

Для этого используется `FilterOut`.

В зависимости от конфигурации могут применяться:

* NER;
* регулярные выражения;
* правила обнаружения чувствительных данных;
* политики обработки определённых типов информации.

Схема:

```text id="w0z2fe"
Ответ LLM
    │
    ▼
FilterOut
    │
 ┌──┴───────────┐
 │              │
 ▼              ▼
Разрешённый   Подозрительный
 │              │
 ▼              ▼
Пользователь   Политика защиты
```

---

# AI Security как отдельный слой

Одна из архитектурных идей FlautCompany заключается в том, что безопасность AI нельзя полностью свести к безопасности обычного приложения.

Даже если сервер, база данных и API защищены, сама языковая модель остаётся объектом воздействия через естественный язык.

Поэтому AI Security выделяется в отдельный слой.

```text id="k9p1mu"
              AI APPLICATION
                    │
          ┌─────────┴─────────┐
          │                   │
          ▼                   ▼
     Application          AI Security
       Security             Layer
                              │
                              ▼
                         FlautGuard
                              │
                              ▼
                             LLM
```

---

# AI и защита данных

Безопасность AI-систем также связана с защитой данных.

Модель может получать доступ к пользовательским данным, контексту, истории взаимодействия или внутренней информации приложения.

Поэтому FlautCompany рассматривает AI Security и Data Security как связанные, но отдельные задачи.

```text id="u7x4bd"
                 AI Application
                       │
          ┌────────────┴────────────┐
          │                         │
          ▼                         ▼
     FlautGuard               .fsecurity
          │                         │
          ▼                         ▼
      AI Security              Data Security
          │                         │
          └────────────┬────────────┘
                       ▼
                   Application
```

FlautGuard контролирует AI-контур.

`.fsecurity` предназначен для защиты данных приложения.

---

# AI-агенты

Отдельным направлением FlautFast являются AI-агенты.

В отличие от обычного чат-интерфейса, AI-агент может взаимодействовать с внешними инструментами и выполнять последовательность действий.

Это увеличивает потенциальную поверхность атаки.

Например, AI-агент может иметь доступ к:

* API;
* базам данных;
* файловым системам;
* внутренним сервисам;
* инструментам автоматизации.

Поэтому в агентных системах важно контролировать не только текст ответа модели, но и действия, которые модель инициирует.

---

# Принцип минимальных полномочий

Для AI-систем FlautCompany рассматривает принцип минимальных полномочий как один из базовых элементов архитектуры.

Модель или AI-агент не должны получать больше доступа, чем требуется для выполнения конкретной задачи.

Упрощённая модель:

```text id="a2c7nm"
LLM
 │
 ├── Tool A ── разрешён
 │
 ├── Tool B ── разрешён
 │
 ├── Database ─ ограничен
 │
 └── System ─── запрещён
```

Даже если модель будет успешно атакована через prompt injection, ограничение её полномочий снижает возможные последствия.

FlautGuard может рассматриваться как один из компонентов такого защитного контура.

# Ограничения

Ни один защитный слой не обеспечивает абсолютную безопасность.

Безопасность AI-систем зависит также от:

* архитектуры приложения;
* модели угроз;
* настроек LLM;
* прав доступа;
* подключённых инструментов;
* качества классификаторов;
* политики обработки данных;
* безопасности инфраструктуры;
* контроля зависимостей;
* мониторинга.

FlautGuard предназначен для уменьшения поверхности атаки и дополнительного контроля AI-системы, а не для замены всей инфраструктурной безопасности.

---

# Развитие направления

FlautFast и FlautGuard находятся в рамках единой технологической экосистемы FlautCompany.

AI-направление отвечает за разработку технологий искусственного интеллекта.

FlautSecurity отвечает за защиту AI-систем и пользовательских данных.

Такое разделение позволяет развивать AI и его безопасность одновременно:

```text id="r2m6vx"
FlautCompany
│
├── FlautFast
│     └── AI / LLM
│
└── FlautSecurity
      ├── FlautGuard
      │     └── AI Security
      │
      └── .fsecurity
            └── Data Security
```
